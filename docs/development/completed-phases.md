## v0.35.x — The gameplay arc

| Version | Shipped | Milestone |

| v0.35.0 | 2026-07-27 | **Monster sight + wake — opens the gameplay arc, and brings its gate with it.** The 0.34.x band was gated on byte-identical pixels; this arc changes what monsters DO, so it adds **`--ai-probe N` / `--ai-at X Y`**: a deterministic behaviour fingerprint (wake/chase/melee/ranged/sight/move-blocked/reject-skip/fov-reject counts + a per-state census + position dump). `--ai-at` is required because **no monster on E1M1/3/5/7/9 has line of sight from the map's own spawn point** — every counter is zero there. **OP-5b**: idle monsters re-scanned the whole map every tick — the baseline measured `sight_calls == monsters × ticks` with `sight_true == 0` throughout (E1M5: 91 × 350 = 31,850 full linedef walks in 10 s, none ever finding anything). Fixed by loading the WAD's **REJECT lump** (never read before this) as vanilla's O(1) sector-visibility pre-test, plus **staggering** idle look-scans over 4 ticks by thing index (vanilla A_Look runs on the monster's own cadence; doom had every sleeper scanning on the SAME tick). Idle sight calls **−83% to −89%** across five maps; **`things_tick` 12.3 → 4.6 µs (−63%)**, −76% against the band start. Staged engagements keep identical wakes/chases/census; the one intended cost is a wake landing up to 3 ticks (~0.09 s) later, which shifts attack cadence — exactly why this half was kept out of v0.34.7's byte-identical batch. **EF-2** (deferred from v0.34.1): monsters no longer see through the back of their own heads — vanilla A_Look's front-180° arc now gates the sight wake, while noise still wakes from any direction (subject to the v0.34.1 TF_AMBUSH deaf check). Backed by a **per-thing sector resolver** in a parallel array (the thing struct is full at stride 128, and growing it is the layout-change class v0.34.5 needed 18 sentinel asserts to make safe) — RC-G1 needs exactly this resolver. Tests **240 WAD-free / 366 full** (+13/+17) with two mutation-proven groups: REJECT-agreement (wherever REJECT says blocked, the real walk must agree — a wrong bit blinds a monster silently) and `ai_in_front`, extracted specifically so it could be unit-tested because a point behind a monster is usually also sight-blocked, so probe-testing it would look verified while never running. Render byte-identical; fuzz ×7; binary 472,920 B; AGNOS QEMU PASS. **Scope**: the roadmap grouped four items here; RC-G1 + F331-4 are about how a monster MOVES, need their own evidence, and were re-slotted to v0.35.1 rather than put four behaviour changes behind one fingerprint diff. |

| v0.34.10 | 2026-07-27 | **`asr()` → native `>>>` — closes the 0.34.x band. Byte-identical at tick 0 AND tick 24.** All **96** `asr()` call sites in `src/` migrated to the native arithmetic right shift. `asr()` was a FUNCTION CALL synthesising a sign-preserving shift (Cyrius `>>` is logical); in isolation the helper costs **5.27 ns** vs **1.66 ns** for the operator — and `fixed_mul` is literally `asr(a * b, 16)`, one multiply plus that call. Interleaved A/B, post winning every one of 4 pairs: **`fixed_mul` 6 → 4 ns (−33%)**, **true spawn frame 615 → 542 µs (−12%)**, `render_frame` 428 → **369 µs**. **Pre-gate ran first**, before touching a single site: `>>>` proven to FLOOR negatives exactly as bsp's `asr()` does (`-1000000 >>> 16 == -16`, not `-15`) — had it truncated toward zero the migration would have silently corrupted every negative-coordinate computation in the engine, with nothing failing loudly. That property is now pinned permanently (`regression_asr.tcyr` 18 → **33** asserts: the same floor cases plus four asserting `>>>` and `asr()` agree pairwise). The rewrite is fully parenthesised (`asr(E,N)` → `((E) >>> (N))`) so precedence cannot shift meaning, and the byte-identical A/B proves it did not. `asr()` itself is untouched — it lives in the vendored `lib/bsp.cyr` and bsp's internals use it. CLAUDE.md's shift rule inverted: `>>>` canonical, `asr()` retired, carrying the gate that `>>>` was **const-fold-UNGUARDED in cyrius 6.4.46–6.4.73** so this could not have shipped on an older pin. Tests 227/349/33/12; fuzz ×7; binary 464,352 B (agnos 450,864, both unchanged); AGNOS QEMU direct-map PASS + pixel-diff vs Linux **100.00% exact**. **Band totals (v0.34.6 → v0.34.10, every cut byte-identical): `render_frame` 1.032 ms → 369 µs (−64%), true spawn frame 1.22 ms → 542 µs (−56%)**, plus the SLADRIP animation fixed after being a no-op for the engine's entire life, fuzz ×5 → ×7, four silent capacity truncations lifted, TEXTURE2 parsed for the first time, and `--ppm` no longer opening the developer's live framebuffer device. |
